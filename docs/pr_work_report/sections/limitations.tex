\section{Limitations}

The current practical work has several limitations. Some are limitations of the
present experimental state, while others are broader limitations of the data and
evaluation setup used for symbolic music generation:
\begin{itemize}
	\item the active experiments use a 2,000-file subset rather than the full available corpus;
	\item genre labels are multi-label and LastFM-derived, so they are noisy descriptive tags rather than clean class labels;
	\item deduplication signatures reduce but may not eliminate all musical duplicates or near-duplicates;
	\item current reported metrics are validation token metrics, not final held-out generation results;
	\item REMI+ choices were tuned on a small sampled run and may need revisiting for final-scale training;
	\item no human evaluation protocol is currently defined;
	\item the current model comparisons are not yet matched against the Transformer baseline under the same split, tokenizer, compute budget, and evaluation protocol;
	\item the medium xLSTM follow-up combines a larger model, longer training, and a restart schedule in one experiment, so its overfitting behavior cannot isolate which factor caused the degradation;
	\item the training context length is fixed at 1024 tokens, which may truncate or fragment longer musical structure such as repeated sections, transitions, and form-level dependencies;
	\item the current models are unconditional next-token models and do not yet use the available genre, instrument, or metadata tags as conditioning signals;
	\item the tokenizer and evaluation code depend on MIDI parsing and decoding behavior, so failures or artifacts in corrupted, unusual, or very dense MIDI files can affect both training data and generated-output metrics;
	\item the current generation-quality criteria do not yet include systematic checks for listening-level properties such as phrasing, long-range repetition, harmonic direction, or arrangement coherence.
\end{itemize}

The strongest methodological limitation is that validation loss is only a proxy
for musical usefulness \citep{dongMuseGANMultitrackSequential2017,ensMMMExploringConditional2020}. A model can assign high probability to the next reference
token while still producing samples that repeat short patterns, decode into
awkward timing, overuse frequent instruments, or fail to develop convincing
musical structure. Conversely, a model with slightly worse validation loss could
produce more acceptable continuations under a particular sampling strategy. For
this reason, the current validation-ranked checkpoints should be interpreted as
candidates for final evaluation rather than as final conclusions about generation
quality.

The dataset construction also reduces leakage rather than proving its complete
absence. Grouping by music ID and hashing normalized note content catches exact
and near-exact duplicates under the implemented signature, but it cannot identify
all covers, alternate arrangements, transpositions, metadata mismatches, or files
that share substantial musical material after larger edits. The LastFM tags are
useful for balancing and reporting, but they are user-derived descriptors and are
not guaranteed to be consistent across tracks or complete for underrepresented
styles. As a result, split-balance statistics should be read as diagnostics of
the constructed subset, not as proof that the subset is fully representative of
the broader LMD population.

There are also compute and scale limitations. The sweeps are practical for a
rented-GPU workflow, but they cover only a small part of the joint design space:
model size, schedule, batch size, tokenizer structure, context length, sampling
strategy, and training duration are all coupled. The current experiments give a
useful path toward a final checkpoint, especially by identifying tokenizer 14 as
a stronger downstream representation than tokenizer 11, but they do not establish
that the selected settings are globally optimal. Larger-subset or full-corpus
training may change the best tokenizer, the amount of overfitting, and the
relative value of larger xLSTM configurations.

Finally, the project currently focuses on an xLSTM-centered pipeline. This is
appropriate for the practical objective of the work, but it limits the strength
of any architectural claim. Without a matched Transformer comparison and a final
held-out generation evaluation, the report can document that the implemented
xLSTM system trains and produces validation-competitive checkpoints, but it
should not yet claim superiority over alternative symbolic-music models.
